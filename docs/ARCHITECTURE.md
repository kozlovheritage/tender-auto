# Как устроен Tender Auto

## Текущая десктопная версия

```text
gui.py
  ├─ sampler.py → ЕИС → локальная Excel-выгрузка
  └─ tender_auto.py → документы ЕИС → текст → AI → Python-проверки
                                           └→ PDF + DOCX + Excel + ZIP
```

`tender_auto.py` остаётся основным рабочим оркестратором. Код постепенно
выделяется в `tendercore`; наличие пакета не означает, что монолит уже заменён.
`shadow_wiring.py` поддерживает переходную теневую цепочку.

| Путь | Назначение |
|---|---|
| `gui.py` | PySide6, дочерние процессы, статус и журнал |
| `sampler.py` | Поиск, обход страниц и формирование выгрузки |
| `tender_auto.py` | Рабочий анализатор и интеграция модулей |
| `tendercore/eis/` | Транспорт, координация, содержимое документов |
| `tendercore/extract/` | Извлечение текста и разделов |
| `tendercore/analysis/` | Промпты, предварительные и итоговые проверки |
| `tendercore/auctions.py` | Консервативная классификация аукционов |
| `tendercore/logistics.py` | Независимая сценарная оценка рейса |
| `tendercore/report/` | DOCX/PDF, комплект отчётов, шрифты и ресурсы |
| `tendercore/cemtorg_output.py` | Очистка нерелевантных блоков в сценарии производителя |
| `tendercore/suppliers/`, `tendercore/rfq/` | Опциональные модули поставщиков и запросов |
| `profiles/` | Локальные профили; в Git только безопасные примеры |
| `tests/` | Новые регрессии и исторические тесты |

## Профили

Клиентский профиль управляет ассортиментом, стоп-факторами и дополнительными
функциями. Цемторг — производитель/поставщик, поэтому поиск других поставщиков,
их email и RFQ в этом сценарии не нужен.
Приватные конфигурации не являются частью публичного кейса.

## Будущее серверное ядро — пока не реализовано

Согласованный вариант: десктоп управляет работой и выполняет сетевые запросы
к ЕИС с устройства клиента; закрытая логика и профили работают на сервере.
Документы передаются на обработку временно, результат возвращается клиенту.
Постоянное хранение исходных документов, результатов и клиентских технических
журналов на сервере не планируется по умолчанию.

Это направление отложено из-за отсутствия бюджета на инфраструктуру.
В текущем репозитории нет действующего серверного управления подписками,
отзывом доступа или автоматическими обновлениями клиентов.
